# Runtime smoke and gate results

Local stack (no GPU, no Docker): `uvicorn` on SQLite + `INFERNA_MOCK_ENGINE=true` worker +
one deployed mock instance (`Qwen/Qwen2.5-0.5B-Instruct`, port 8010). Gateway enabled.

## 1. Gateway accounting (same API key, repeated use)

Three sequential `/v1/chat/completions` calls **on one key**, each separated by >60 s so the
`last_used_at` stamp was persisted between them (the 60 s refresh window):

```
same-key statuses: [502, 502, 502]        # upstream is a mock instance with no HTTP server
```

Before the fix below the same sequence was `502, 500, 500` — see §4.

Buffered vs stored, immediately after a request and after the 30 s flush:

```
records after flush window: {'requests': 3, 'tokens_in': 0, 'tokens_out': 0, 'avg_latency_ms': 2041}
usage rows: [('Qwen/Qwen2.5-0.5B-Instruct', 3, 0, 0)]
limits: {'token_limit': None, 'request_limit': None, 'requests_used': 4, 'tokens_used': 0}
```

`requests_used` (records **plus** the not-yet-flushed buffer) runs ahead of `totals.requests`,
which is exactly the designed split: `/api/v1/usage.totals` counts stored records, the quota
view counts everything, so a burst cannot bypass a limit while it sits in the buffer.

## 2. Reconciliation against Prometheus (`scripts/usage-reconcile.py`)

Traffic is generated by the script itself (`--traffic-cmd`), so the counters are quiet before
the window opens and stop before the post-window snapshot:

```
waiting 35s + stability for the pre-window records …
running traffic command: python <traffic generator> 40
traffic: 10 requests {502: 10}
waiting 35s + stability for the post-window records …

pre-window : metrics requests=145 records requests=145
post-window: metrics requests=155 records requests=155

| signal           | /metrics delta | usage records delta | drift  |
| gateway requests | 10             | 10                  | 0.00%  |
| gateway tokens   | 0              | 0                   | 0.00%  |
| usage events     | 10             | 10                  | 0.00%  |

OK: totals agree within 1.00%.
exit=0
```

Idle cross-check of the whole process lifetime (attributes of `inferna_requests_total` vs
`inferna_usage_events_total` vs the stored records):

```
inferna_requests_total       SUM 127
inferna_usage_events_total   SUM 127
records requests             SUM 127
```

Iterations that shaped the tool (kept because they are the reason for its protocol): while
traffic was still running, `/metrics` deltas legitimately exceeded the record deltas by the
amount still sitting in the buffer (17 vs 15, 9 vs 7). The script now waits for both sides to
stop moving and refuses to compare otherwise (`exit 2`, "no gateway traffic in the window").

## 3. Quotas

`PUT /api/v1/users/{id}/limits` (admin) sets/clears soft daily limits; a user whose daily
request/token budget is spent gets an OpenAI-shaped `429` with `code=quota_exceeded` and the
request is counted as `quota_rejected` (never as billable traffic). Covered by tests:
`test_quota_rejects_once_the_daily_limit_is_reached`, `test_quota_allows_traffic_when_no_limit_is_set`,
`test_set_limits_endpoint` (403 for non-admins, 404 unknown user, 422 negative).

## 4. Bug found by this smoke (pre-existing, fixed here)

The first traffic run returned `{502: 10, 500: 18}`. Log:

```
File ".../api/gateway.py", line 172, in get_api_key
    if key.last_used_at is None or (utcnow() - key.last_used_at).total_seconds() >= ...
TypeError: can't subtract offset-naive and offset-aware datetimes
```

On SQLite (the dev/test default) `DateTime(timezone=True)` round-trips **naive**, so the
comparison blew up on every request *after* the first one per key — i.e. after the stamp had
been persisted. Fixed with `models.as_aware_utc()`; regression test
`test_reused_key_with_stored_stamp_still_serves` reproduces it (two calls on one key, stamp
persisted in between).

# Decisions recorded by this slice

- **Aggregates, not raw events**: the gateway appends to a bounded in-memory buffer
  (`record_request`, no awaits) and `usage_flush_loop` folds it into daily `usage_records`
  rows every 30 s — the same shape as the last-used stamp flush. A crash loses at most one
  interval, exactly like the Prometheus counters resetting.
- **Accounting moved into `finally`**: `_relay` records on completion, on upstream failure,
  on `GeneratorExit` (client hung up) and on 502, so the old "usage is lost when the client
  disconnects" hole is closed. Outcomes are counted in `inferna_usage_events_total`
  (`ok`, `no_usage_chunk`, `client_disconnect`, `upstream_error`, `quota_rejected`, `dropped`).
- **`stream_options.include_usage` is injected** for streamed chat completions
  (`INFERNA_GATEWAY_INJECT_STREAM_USAGE=true`, a client's own value wins) — without it token
  numbers are unavailable and a stream counts as requests only.
- **GPU-hours are not attributed to users**: `Deployment` has no owner column, so
  `gpu_usage_records` aggregates GPU-seconds per (model, cluster, day) from an occupancy
  sampler over `LIVE_STATES`; the API reports the same value to every user of that model.
- **Quotas are soft and per UTC day**, evaluated before the upstream call using records plus
  the pending buffer.
- **Reconciliation ships as `scripts/usage-reconcile.py`** (not `.sh` as first sketched in the
  plan, updated there): it needs JSON and float math, and the repo already has a Python
  `scripts/*.py` precedent. The plan's "panels in the Grafana usage dashboard" landed as two
  panels in `deploy/grafana/dashboards/gateway.json` (accounting by outcome, and the
  events/requests ratio that catches dropped accounting).

# M8 slice: usage reconciliation as a CI gate

Stage 5 shipped the aggregator and `scripts/usage-reconcile.py`; M8 asks for the reconciliation to be
a gate rather than a thing an operator remembers. The `usage-reconcile` CI job does exactly that:

1. brings up the mock stack (`postgres`, `server` with the gateway enabled, mock `worker`);
2. deploys a model through the API and issues a key (the mock worker has no engine, so the gateway
   answers 502 — which must still be **counted**; that is the property being reconciled);
3. runs `scripts/usage-reconcile.py --traffic-cmd "bash scripts/bench.sh …"` with the bench harness as
   the traffic generator, and fails the job when the stored records and the Prometheus counters drift
   beyond 1 %.

Why the mock stack is enough for this gate: the thing under test is the accounting path (buffer →
flush → records) and its agreement with `inferna_requests_total`/`inferna_tokens_total`, not the
engine. A 502 exercises the `upstream_error` accounting path end to end, and the reconcile script
refuses to compare while counters are still moving.

Per-key and per-user breakdown (`api_key_id` in `usage_records`, `?key_id=` on the endpoint) landed
with stage 5, so M8 needs no schema change here; whole-group autoscaling — the other half of M8 — is
`docs/roadmap/plans/evidence-p02b-autoscaling.md`.
